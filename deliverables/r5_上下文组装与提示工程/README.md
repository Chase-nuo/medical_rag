## 核心结果

### 环境约束（决定了全部设计）

| 项 | 实测 |
|---|---|
| LLM | `deepseek-r1:7b`（本地 Ollama，CPU 8 线程） |
| 生成速度 | 6.3~6.6 tokens/s |
| **thinking** | **无法关闭**（`think=False` 无效），占 60~70% token |
| `num_ctx` 默认 | 2048 → 必须显式设 **8192**，否则静默截断 |
| token 计数接口 | `/api/tokenize` 返回 404 → 只能本地估算 |
| 单阶段生成 | **160.8 秒**（1060 tokens） |

### 上下文组装器

| 机制 | 实现 | 实测 |
|---|---|---|
| token 估算 | 校准式 + 安全系数 1.3 | 偏差 **-0.1%**（修正前 -23.2%） |
| Jaccard 去重 | 字符 4-gram，阈值 0.7 | 4 条相似块 → 1 条；改写字序 0.65 保留 |
| 多样性 | 同来源第 n 块 ×0.6ⁿ，单篇上限 3 | 另一篇从第 5 提到第 2，且未被挤出 |
| 句末截断 | 末段 10% 内找句末标点 | 三档预算截断均落在 `.` |
| budget 2500 | 40 条候选 → 21 条，2448 tokens | 多样性丢 3，预算丢 16 |

### 四个提示模板

| 阶段 | temperature | max_tokens |
|---|---|---|
| 证据评估器 | 0.0 | 1400 |
| 答案生成器 | 0.2 | 1600 |
| 批判性审查器 | 0.0 | 1400 |
| 最终组装器 | 0.1 | 1600 |

`max_tokens` 含 thinking 与正文两段总预算（实测给 150 会得到空答案）。

单阶段生成实测：答案 814 字符，带 9 处 `[n]` 引用，中文结论先行。

## 两处必须说明的问题

**1. token 估算一度低估 23%。**
按纯中英文散文校准（1.57 / 5.03 字符每 token），套到含 `PMC11219383` 这类 ID 和符号的真实上下文上时低估 23.2%（估 2418 / 实际 3147）。**低估会导致超窗，而超窗是静默截断**——末段证据消失且不报错。已加安全系数 1.3，复测偏差 -0.1%。

**2. 单阶段答案里有一条可疑陈述。**
生成的答案称二甲双胍"增加低密度脂蛋白胆固醇"，医学上可疑，且同一条证据 `[6]` 被用到 4 个不同机制上。这**正好论证了批判性审查器的必要性**（其六类检查正针对"过度概括""无引用支持"）。但由于四阶段要 10~15 分钟，本次未跑完整串联，**审查器能否纠出该错误尚未验证**。

## 已知局限（报告 §7）

1. **四阶段串联未跑通验证** —— 单阶段 160 秒，串联 10~15 分钟
2. **答案事实正确性无自动评判** —— 引用正确不等于陈述正确，需医学背景人工评审
3. **延迟高** —— 单阶段 160 秒，实用场景需下调候选数或换非推理模型做定稿
4. **token 估算换数据分布可能再偏** —— 需定期用 `prompt_eval_count` 复校
5. **去重在真实候选上触发 0 次** —— 机制未在真实数据上被检验
